한 줄 요약
이 프로젝트는 React Native 안드로이드 앱입니다. 족보 데이터는 기본적으로 기기 안(AsyncStorage)에 저장됩니다. 서버 동기화와 족보 공유는 코드에 들어 있지만 지금은 꺼져 있습니다. 유지보수는 Cursor에 폴더를 열고, 한국어로 시키면 됩니다.

01이 문서를 읽는 분께

이 문서는 “코드를 다른 사람에게 넘긴 뒤에도, 그 사람이 VS Code/Cursor로 고치고 빌드하고 테스트할 수 있게” 만드는 것이 목적입니다.

권장 작업 순서

  1. 4장을 보고 PC에 Node, JDK, Android Studio를 설치합니다.
  2. Cursor(또는 VS Code)를 설치하고 저장소 폴더 Pedigree_App을 엽니다.
  3. 5장대로 앱을 한 번 실행해 봅니다. 홈 화면이 뜨면 환경은 된 것입니다.
  4. 6장 테스트를 한 번 돌립니다. 여기서 깨지면 코드가 아니라 환경 문제일 때가 많습니다.
  5. 7·8장으로 “어디를 고치면 되는지”를 파악한 뒤, 9장처럼 Cursor에게 일을 시킵니다.
Cursor를 쓰는 이유

VS Code와 거의 같은 편집기입니다. 여기에 AI가 붙어 있어, 한국어로 “이 버그 고쳐줘”라고 하면 코드를 찾아 고칩니다. 인수받은 분이 코드를 전부 외울 필요는 없습니다.

VS Code만 써도 됩니다

빌드·실행·테스트는 VS Code 터미널에서도 동일합니다. Cursor는 VS Code 기반이라 단축키와 확장 개념이 같습니다. 이 문서는 둘 다 기준으로 적었습니다.

비밀번호 · 키는 이 문서에 없습니다
데이터베이스 비밀번호, 서명 키스토어, Google OAuth 비밀값은 코드/채팅에 넣지 말고 인수자에게 별도로 전달하세요. back/.env는 Git에 올리지 않습니다.

05VS Code / Cursor에서 열고 실행하기

Cursor와 VS Code의 차이는 AI뿐입니다. 폴더 열기, 터미널, npm 명령은 같습니다. 아래는 프론트(front) 폴더가 작업 기준입니다.

1) 프로젝트 열기

  1. Cursor 또는 VS Code 실행 → 파일 → 폴더 열기.
  2. 가능하면 저장소 루트 Pedigree_App을 엽니다. 터미널에서 앱 명령을 칠 때는 반드시 front로 들어갑니다.
  3. 권장 확장 (둘 다 확장 마켓에서 검색):
    • ESLint
    • Prettier – Code formatter
    • (선택) React Native Tools

2) 의존성 설치 (처음 한 번, 또는 package.json이 바뀐 뒤)

터미널: Ctrl + ` (백틱). PowerShell이면 됩니다.

cd C:\Project\Pedigree_App\front
npm install

node_modules가 생기고 오류가 없으면 다음으로 갑니다. Node가 20 미만이면 실패할 수 있습니다.

3) 에뮬레이터/기기 켜기

adb devices

목록에 emulator-5554 또는 실제 기기 ID가 device로 보여야 합니다. unauthorized면 폰에서 USB 디버깅을 허용하세요.

4) Metro 시작 (JS 번들 서버)

터미널 창을 하나 전용으로 씁니다. 이 창은 끄지 않습니다.

cd C:\Project\Pedigree_App\front
npm start

QR/메뉴가 나오면 성공입니다. 이후 JS를 저장하면 Fast Refresh로 앱이 거의 바로 반영됩니다.

5) 앱 빌드 후 설치

다른 터미널을 엽니다. Metro는 그대로 둡니다.

cd C:\Project\Pedigree_App\front
npm run android

첫 빌드는 Gradle 때문에 수 분 걸립니다. 끝나면 에뮬레이터/폰에 앱이 뜨고 Metro에 연결됩니다.

성공 기준
언어 선택 또는 로그인/게스트 화면 → 홈 타일(가족 계보, 연락처 등)이 보이면 개발 환경은 된 것입니다.

다시 실행할 때 (일상)

  1. 에뮬레이터 또는 폰 연결
  2. front에서 npm start
  3. 앱이 이미 깔려 있으면 앱만 열고 Metro에 붙습니다. 안 붙어 있으면 npm run android를 다시 합니다.

Android에서 개발 메뉴: 에뮬레이터는 Ctrl + M, 또는 adb shell input keyevent 82. 강제 새로고침은 R 두 번.

코드만 고쳤을 때 / 네이티브를 건드렸을 때

바꾼 것할 일

앱에서 직접 확인할 것 (엔진을 건드린 뒤)

  1. 게스트로 들어가 가족 계보가 기본 칸(조부모~자녀)으로 뜨는지
  2. 이름을 넣고 사진을 넣은 뒤 앱을 완전히 종료했다가 다시 켜도 남는지
  3. 형제/자녀를 추가하면 선이 연결되고 칸이 겹치지 않는지
  4. 친가 / 외가 / 배우자 집안 전환 시 같은 사람 정보가 따라가는지
  5. 다른 사람을 기준으로 시점 변경 후, 다시 원래 “나”로 돌아올 수 있는지
  6. 설정에서 언어를 바꿔 홈·족보 문구가 바뀌는지
가장 흔한 사고
레이아웃/템플릿을 고치면서 사람 객체를 통째로 덮어쓰면 사진과 이름이 사라집니다. 재시작 후 사진이 남아 있는지 반드시 확인하세요. 규칙은 7장과 personPersist.ts입니다.

07프론트엔드 구조와 핵심 규칙

화면 연결

index.js → App.tsx(언어, 로그인, 체험기간) → AuthenticatedApp.tsx(홈과 하위 화면 라우팅). React Navigation을 쓰지 않고 단순 route 상태입니다.

LanguageSelect → Login/Guest → Home
  ├ PedigreeScreen   (족보, 가장 큰 화면)
  ├ Contacts / Search / Anniversaries / Memos
  └ Settings

데이터 모델

사람 한 명은 front/src/types/pedigree.ts의 Person입니다. 관계 필드는 fatherId, motherId, spouseId입니다. 화면 좌표는 Person에 넣지 않습니다. 세대 배치는 엔진이 매번 계산합니다. 사용자가 노드를 살짝 민 오프셋만 별도 키로 저장합니다.

저장 단위는 사람 한 장이 아니라 스토어입니다. front/src/types/lineage.ts:

  • version: 2
  • activeView: 지금 보고 있는 집안
  • views: 네 벌의 사람 맵
    • self — 나 시점 (기준, 가장 중요)
    • paternal — 친가
    • maternal — 외가
    • spouse — 배우자 집안

슬롯 ID 예: 나 시점의 본인은 me_sib2 부류입니다. 접두사 me / pat / mat / spo. 생성은 standardTemplate.ts.

personPersist.ts이름·전화·생일·사진·메모·성별 보호. 모든 병합의 입구

연결선은 EdgeLines.tsx, 드래그 노드는 DraggablePersonNode.tsx. 레이아웃이 끝난 뒤에 선을 그립니다.

사용자 데이터 보호 — 가장 중요한 규칙

Cursor 규칙 파일: front/.cursor/rules/persist-user-data.mdc (항상 적용). 코드 강제: front/src/utils/personPersist.ts.

보호 필드: photoUri, name, phone, birthDate, note, gender(unknown 제외)

  • 템플릿 맞출 때: 구조(부모/배우자 ID)는 템플릿, 사용자 입력은 기존 값 우선.
  • 뷰 복사: 원본에 값이 있을 때만 덮어씀. 빈 값으로 지우지 않음.
  • 서버 pull: 로컬 사진을 무시하지 않음.
  • 금지: { ...existing, ...template }처럼 템플릿이 나중에 와서 사용자 필드를 덮기.
이 규칙을 어기면
앱을 다시 켰을 때 사진이 빠지거나, 친가 보기로 전환할 때 이름이 기본 호칭으로 리셋됩니다. 레이아웃 리팩터 전에 이 모듈을 재사용했는지 확인하세요.

다국어

문구는 front/src/i18n/messages.ts에 ko/en/ja/zh가 같이 있습니다. 화면에 한글을 직접 넣지 말고 t('키')를 씁니다. 호칭 번역은 i18n/kinship.ts. 새 문구를 넣으면 네 언어 모두, 그리고 가능하면 i18n.test.ts를 맞춥니다.

테마

색·세대 파스텔은 front/src/theme/ui.ts. 족보 배경은 보기마다 다릅니다(ACTIVE_VIEW_BG).

08백엔드와 동기화

백엔드는 EC2 등에서 FastAPI로 돌리도록 만들어져 있습니다. 앱 기본값은 서버를 쓰지 않습니다 (ENABLE_SERVER_SYNC = false). 로컬만으로 족보·사진·메모가 동작합니다.

프론트에서 서버 주소

front/src/config/api.ts의 API_BASE_URL. HTTPS(Nginx + Let’s Encrypt, sslip.io 호스트)를 전제로 적혀 있습니다. 서버를 옮기면 여기와 백엔드 PUBLIC_BASE_URL을 같이 바꿉니다.

로컬에서 API 띄우기

cd C:\Project\Pedigree_App\back
copy .env.example .env
# .env 를 실제 DB·도메인에 맞게 수정 (비밀번호는 인수자에게 별도 전달)
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload

DB는 MySQL. 최초 1회 sql/schema.sql 실행. 앱의 공유 테이블은 서버 기동 시 없으면 만들기도 합니다.

Google 로그인

Web Client ID는 front/App.tsx의 GOOGLE_WEB_CLIENT_ID와 백엔드 GOOGLE_CLIENT_ID가 맞아야 합니다. Android 패키지명 com.pedigree_app과 디버그 SHA-1을 Google Cloud 콘솔 OAuth 클라이언트에 등록하지 않으면 DEVELOPER_ERROR가 납니다. 인수 시 콘솔 접근 권한과 SHA-1을 함께 넘기세요.

디버그 SHA-1 확인 예:

cd C:\Project\Pedigree_App\front\android

동기화를 다시 켤 때
  1. ENABLE_SERVER_SYNC = true
  2. API URL, 인증서, DB, Google 클라이언트가 살아 있는지
  3. 게스트는 서버에 안 올라갈 수 있음 — 구글 연동 후 확인
  4. 사진: 서버 URL과 로컬 URI가 섞이지 않게 personPersist 경로 유지

09Cursor 설치와 유지보수

Cursor는 VS Code를 기반으로 한 편집기입니다. 폴더를 열고, 채팅에 한국어로 시키면 프로젝트 파일을 읽고 고칩니다. 코드를 몰라도 유지보수를 시작할 수 있게 하는 도구입니다. 다만 결과를 실행·테스트로 확인하는 책임은 사람에게 있습니다.

설치

  1. 브라우저에서 https://cursor.com 접속 → Download → Windows용 설치.
  2. 설치 후 계정으로 로그인합니다. (회사 메일 권장)
  3. 파일 → 폴더 열기 → Pedigree_App 선택.
  4. 처음이면 “프로젝트 신뢰”를 허용합니다. 터미널·확장이 동작합니다.
  5. VS Code 설정을 가져오겠다고 하면, 이미 VS Code를 쓰던 분은 가져와도 됩니다.

공식 문서: 에디터 사용법, Agent, 규칙은 Cursor 설정과 문서에서 최신본을 보세요. UI 명칭은 버전에 따라 Chat / Agent / Composer로 조금 다를 수 있습니다. 공통점은 “대화로 코드를 고친다”입니다.

11인수인계 체크리스트

넘기는 사람과 받는 사람이 같이 표시하세요.

넘기는 사람

  1. Git 저장소 접근 (원격 URL, 권한)
  2. 이 PDF와 소스 위치
  3. Google Cloud OAuth (웹/안드로이드 클라이언트, SHA-1)
  4. 서버를 쓸 경우: SSH, Nginx, .env 값, DB 계정 — 메일이 아닌 안전한 채널
  5. 스토어 올릴 계획이면 서명 키스토어와 비밀번호 (Git 금지)
  6. 현재 ENABLE_SERVER_SYNC / ENABLE_PEDIGREE_SHARE 가 false라는 점 구두 확인
  7. 미커밋 작업이 있으면 커밋하거나, 무엇이 진행 중인지 메모

받는 사람 — 첫날

  1. 4장 도구 설치, adb devices 성공
  2. front에서 npm install → npm start → npm run android
  3. 게스트로 족보 한 명 수정 후 재시작, 사진/이름 유지 확인
  4. npm test 통과
  5. Cursor로 이 폴더를 열고, Ask에 “로그인 흐름을 App.tsx 기준으로 설명해줘” 테스트

받는 사람 — 첫 수정

  1. 이슈 하나를 한국어로 Agent에게 맡긴다
  2. diff를 읽고 보호 필드·슬롯 ID가 함부로 바뀌지 않았는지 본다
  3. 테스트 + 에뮬레이터 확인 후 커밋
